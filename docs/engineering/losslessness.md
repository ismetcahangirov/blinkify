# Losslessness: the evidence

From [#45](https://github.com/ismetcahangirov/blinkify/issues/45), Epic
[#6](https://github.com/ismetcahangirov/blinkify/issues/6). This page is the
evidence for Blinkify's one claim — that what an edit does not have to change
reaches the output unchanged. The results table below is **written by the
suite**, not by hand, and the suite fails when the committed table is not what
it produced, so the table cannot become a claim that is no longer true.

```bash
cargo test -p blinkify-engine --test losslessness                          # run, and check the table
BLINKIFY_UPDATE_LOSSLESSNESS=1 cargo test -p blinkify-engine --test losslessness   # regenerate it
pnpm corpus -- --verify                                                   # the corpus reproduces byte for byte
```

## The hash boundary

Defined once, in `crates/blinkify-engine/src/export/verify.rs`, and cited by
every test in Epic #6:

- **In**: every byte of every packet's payload — the coded picture or sound.
- **Out**: what the container says _about_ a packet — presentation and decode
  timestamps, byte position, stream index, flags. An export rebases timestamps
  to zero by design (#40) and a constant speed rescales them deliberately
  (#42); a hash that included them would fail by construction and prove
  nothing.
- **Out**: in-band parameter sets — H.264/HEVC VPS, SPS and PPS NAL units,
  AV1 sequence headers and temporal delimiters. They are the stream's
  configuration, not its pictures, and a smart-cut re-sends the source's own
  before the first copied keyframe after a seam (#41).

Packets are read as a stream copy reads them — FFmpeg's demuxer, then the
engine's NUT reader — and compared in decode order: the source's packets of a
range, from the keyframe it starts on, must appear in the output as one
contiguous run.

## The suite checks itself

An assertion that cannot fail proves nothing, so three controls run with it:

| Control  | What it does                                          | Must     |
| -------- | ----------------------------------------------------- | -------- |
| Positive | a stream copy with every timestamp moved by 7.5 s     | **pass** |
| Negative | the same stream, fully re-encoded                     | **fail** |
| Damage   | one bit flipped inside one packet's payload of a copy | **fail** |

Every output is also decoded in full, and FFmpeg's error stream — not only its
exit code — must be empty: most decode errors are not fatal.

## The corpus

Generated by `pnpm corpus` from the recipes in
[`tools/corpus/generate.mjs`](../../tools/corpus/generate.mjs), never committed
(`CLAUDE.md` forbidden behaviour 12); see [`test-corpus.md`](./test-corpus.md).
`pnpm corpus -- --verify` generates it again elsewhere and requires identical
bytes, so a result here is a result on any machine.

## Results

Only results that are the same on every machine are published. Seams in H.264
and HEVC need a hardware encoder (ADR-0003): they are asserted in
`crates/blinkify-engine/tests/export_smartcut.rs` wherever one exists, and the
decline is asserted where not.
