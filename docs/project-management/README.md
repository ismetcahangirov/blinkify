# Project management

What is being built, in what order, and what makes an issue good enough to work
from.

## What belongs here

- [`roadmap.md`](./roadmap.md) — the Epics, their order, and their dependencies
- `issue-rules.md` — requirements versus acceptance criteria (added in #12)
- Planning notes, scope decisions and their rationale
- Retrospectives on an Epic once it closes

## What does not belong here

- **Issue content.** GitHub is the source of truth for issues. Documents here
  link to issues; they never restate them, because a restatement goes stale
  silently.
- **Architectural reasoning** — that is [`../decisions/`](../decisions/).

## Conventions

- Every Epic in the roadmap links to its GitHub issue.
- Status in this directory is coarse — not started, in progress, done. Fine
  status lives on GitHub, where it updates itself.
